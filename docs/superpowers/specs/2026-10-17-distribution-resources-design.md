# Distribution resources

## Intent and authority
Implement the twenty new distribution ideas from the conversation. The user explicitly authorizes all design choices and uninterrupted execution. Preserve existing uncommitted changes. Work in the existing feature branch so current analytics/editor improvements remain available; do not stage, revert or commit those changes.

## Architecture
A multilingual `/recursos` resource hub uses the existing root layouts, visual tokens, locale routes, navigation and project data. Collection pages are server rendered and indexed. Interactive utilities run locally in the browser; no submitted content, secrets or analytics payload includes tool inputs. A separate compact embed view includes visible attribution. No new production dependencies.

## Twenty deliverables
1. JSON comparison and environment-key checking utilities with actionable errors.
2. Interactive queue/retry demonstration connected to the VMAGeste and Pulsewatch cases.
3. Downloadable runnable worker starter and architecture decision template.
4. Reproducible JSON cloning benchmark, raw measurements, runtime, methodology and source.
5. Downloadable architecture diagrams derived from existing case study stages, CC BY 4.0.
6. Decision guides with conditions, alternatives and links to project evidence.
7. Topic hubs collecting cases, posts and resources.
8. Technical glossary with concrete examples from this portfolio.
9. Public lab with executable experiments and explicit hypotheses and limitations.
10. Project evolution log sourced from existing case decisions and dated resource launches, no invented history.
11. Captioned short screencasts of actual interactive demonstrations, linked from relevant cases.
12. Downloadable multilingual carousel image sequences derived from case study content.
13. Press kit with localized bio, existing brand image and presentation assets.
14. Talk/workshop proposals and downloadable session outlines; no fabricated past appearances.
15. Newsletter curator packs with short summaries, images and canonical links.
16. Collaboration briefs and a proposal flow via an explicitly reviewed mailto draft; no invented coauthors or external messages.
17. Embeddable tool/demo views and safe copyable iframe snippets with attribution.
18. Community gallery with clearly labeled first-party examples, a submission flow, credit and permission requirements; no fake submissions.
19. A resource launch campaign landing page and a self-guided architecture workshop landing page; no fictional event dates or registration.
20. Repository catalog derived from known public repository links; explicit repository/readme links and contribution guidance, no fabricated live GitHub data.

## Scope and honesty
Assets, playable demos, downloads and contact drafts must work. No placeholder links or fake testimonials, collaborators, usage counts, benchmark claims, talks or external publication. External promotion, third-party submissions and actual speaking engagements require real human participation; provide the concrete materials and entry points. Publication/deployment is not implied by editing an existing local repository. Preserve PT/EN/ES content and canonical/hreflang conventions.

## Verification
Pure-function tests for data validation, JSON diff, env checks and queue transitions; browser tests for localized routing, downloads, mailto drafts, embeds and interaction. Run existing unit suite, lint, typecheck, production build and E2E. Inspect desktop/mobile views and media output. Review coverage against all twenty deliverables.
